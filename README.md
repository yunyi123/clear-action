# 清晰行动 · Clear Action

一个面向 Codex 的中文回答风格 Skill：**结论先说，删去客套和重复，按任务保留必要深度。**

简单问题直接回答；操作指导使用编号步骤；项目分析解释证据、依据与取舍。需要详细时充分展开，完成后直接结束。

这是基于个人使用偏好整理的轻量融合版，由 [yunyi123](https://github.com/yunyi123) 确定需求和融合方向，Codex 协助编写、安装与验证。

## 我做了什么

我（yunyi123）想要清楚、容易读的回答，同时不希望“简洁”变成省略分析。因此，我确定了以下融合方案，并让 Codex 协助落地：

1. **按任务决定详略。** 简单问答简短直接；项目分析和方案比较保留证据、依据、取舍与适用条件；用户要详细时完整展开。
2. **去掉机械模板。** 不要求所有问题套同一种结构，不在每轮重述进度，不强制每次结尾留一个动作。
3. **保留真实不确定性。** 证据不足就说明未知，不硬编故障原因或时间估计；技术原文、否定、例外、数值和单位保持准确。
4. **让助手继续做事。** 风格规则不能限制必要分析、额外制造审批，或把已授权且助手能完成的工作推回用户。
5. **独立安装、随时撤回。** 支持按场景自动选择和手动点名；提供对话内停用规则，不改全局指令，也不添加常驻启动钩子。

这份贡献是对既有风格思路的选择、取舍与中文重写，不宣称发明了“结论先说”或“删除客套”。实际规则和界面元数据由 Codex 根据上述需求编写；格式验证与静态场景审查也由 Codex 协助完成。

## 安装

把下面这句话发给 Codex：

```text
请使用 skill-installer，从 https://github.com/yunyi123/clear-action 安装 skills/clear-action。若已有同名技能，先检查差异，避免覆盖个人修改。
```

也可以将仓库里的 `skills/clear-action/` 文件夹放进宿主支持的个人技能目录。本项目首次在 `~/.codex/skills/clear-action/` 安装；当前官方文档也列出了 `~/.agents/skills/` 用户目录。选择与你的宿主相符的一处即可，避免重复安装。

详见 [官方技能文档](https://learn.chatgpt.com/docs/build-skills)。宿主通常会检测变更；如果技能未出现，重启后再检查。

## 使用与停用

启用当前对话：

```text
本对话使用 $clear-action（清晰行动）。请帮我分析这个项目。
```

也可说“使用清晰行动风格回答”，或在支持的界面中选择“清晰行动”。

当前对话停用：

```text
本对话停用清晰行动。
```

恢复时说“本对话重新使用清晰行动”。停用它不会关闭其他技能。

自动选择保持默认允许，但依赖宿主发现技能和模型判断，**不保证所有新会话自动启用**。明确点名更便于试用。它只调整输出风格，不改变任务权限、工具选择、分析深度或验证要求；更高优先级指令及用户当下的明确要求仍然优先。

卸载：删除你安装的个人技能目录中的 `clear-action` 文件夹。已有对话可能仍含加载的规则，因此在该对话明确停用，并用新对话确认卸载结果。

## 适用场景

| 请求 | 期望表现 |
|---|---|
| “17 × 6 等于多少？” | 直接回答“102。” |
| “教我如何导出 PDF。” | 按顺序给出编号步骤，说明必要前提和结果判断 |
| “比较这两个重构方案，详细说明。” | 先给判断，再充分解释证据、取舍、条件和限制 |
| “应用打不开，是什么原因？” | 区分现象与推测，先检查证据，不编造原因 |
| “帮我完成这个修改。” | 执行已授权工作，不把清单交给用户后提前结束 |

## 验证与限制

- 已通过 skill-creator 的 `quick_validate.py` 格式验证，并检查界面元数据、未完成模板标记和乱码。
- 已对简单问答、项目分析、操作指导、证据不足的故障分析、完成收尾及停用行为做静态规则审查。
- **尚未进行真实模型 A/B 对比、自动触发率测量或跨宿主效果验证。** 静态检查不等于效果验证，不承诺节省某个比例的 token 或提高某个比例的质量。
- 这是指令型 Skill，没有 MCP 服务、上下文索引、持久记忆或自动恢复任务状态的实现。
